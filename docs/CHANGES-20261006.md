# 变更记录 2026-10-06

## 2026-10-06 19:02:14 — 修正 DAV:displayname 的取值

**问题**

`fromR2Object()` 把 `httpMetadata.contentDisposition` 直接当作 `displayname`。R2 存的是原始头，形如 `attachment; filename="x.txt"`，客户端列表里显示的就是这一整串；而没有设置该头的对象（占绝大多数）则完全没有 `displayname`（404 propstat）。

**规范依据**

RFC 4918 §15.2 定义 `displayname` 为 "a name for the resource that is suitable for presentation to a user"，并说明它 "defined on the resource, and hence SHOULD have the same value independent of the Request-URI used to retrieve it"。原始 Content-Disposition 不满足前者；后者要求优先使用资源上已存的属性，因此不是简单地用 key 覆盖。

**变更（`src/index.ts`，+72 / -8）**

| 位置                                        | 内容                                                                                                                                                                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getKeyName()`（新增）                      | 取 key 的最后一段，即资源自身的名字                                                                                                                                                                                     |
| `parseContentDispositionFilename()`（新增） | 从 Content-Disposition 中提取 `filename` 参数：参数顺序无关（RFC 6266 不固定顺序），支持带反斜杠转义的引号串与裸 token，取不到返回 null                                                                                 |
| `getDisplayName()`（新增）                  | `filename` 参数优先（资源上已存的属性，符合 §15.2 对 Request-URI 无关性的建议），否则回退 key 最后一段。**永不**返回原始头                                                                                              |
| `fromR2Object()`                            | `displayname: getDisplayName(object)`（原为 `object.httpMetadata?.contentDisposition`）                                                                                                                                 |
| `getLivePropertyValue()`                    | 签名由 `(object, property)` 改为 `(davProperties, property)`                                                                                                                                                            |
| `generate_propfind_response()`              | `fromR2Object()` 只计算一次并复用于 allprop / propname / prop 三个分支（原来调用 3 次；null 分支每次都会生成新的 `new Date()`，同一响应内可能不一致）；隐式集合的 `displayname` 取 key 最后一段，不再与显式集合表现不同 |
| `handle_get()` 目录列表                     | 显示名改用 `getDisplayName()`，与 PROPFIND 保持一致                                                                                                                                                                     |

**实测行为**

| 对象                      | Content-Disposition                         | displayname                      |
| ------------------------- | ------------------------------------------- | -------------------------------- |
| `plain-name.txt`          | 无                                          | `plain-name.txt`                 |
| `opaque-hash`             | `attachment; filename="report 2026.pdf"`    | `report 2026.pdf`                |
| `opaque-hash`（非 ASCII） | `attachment; filename="季度报告.pdf"`       | `季度报告.pdf`                   |
| `opaque-hash`（转义）     | `attachment; filename="a\"b.txt"`           | `a"b.txt`                        |
| `bare-token-hash`         | `inline; filename=bare-token.txt`           | `bare-token.txt`                 |
| `no-filename-hash`        | `attachment`                                | `no-filename-hash`（回退）       |
| RFC 5987 `filename*=`     | `attachment; filename*=UTF-8''%E5%AD%A3...` | key 名（回退，见下）             |
| 显式目录（MKCOL）         | —                                           | 目录名                           |
| 隐式目录                  | —                                           | 目录名                           |
| 根集合                    | —                                           | 仍无 displayname（404 propstat） |

**已知限制**

1. 不解析 RFC 5987 的 `filename*=UTF-8''...`（编码形式），命中不了即回退到 key 名。回退结果可用，故未引入额外复杂度
2. `wrangler r2 object put --content-disposition <非 ASCII 值>` 会让 wrangler CLI 自身崩溃（与本改动无关的 CLI 缺陷）；非 ASCII 文件名经 HTTP 头写入（如 `curl -H`）完全正常

## 2026-10-06 18:15:15 — 支持 R2 隐式目录（implicit collection）

**背景与方案**

完整分析与方案见 `docs/2026-10-06-implicit-collection-plan.md`。问题：直接从 R2 侧（控制台 / S3 API / `wrangler r2 object put`）写入对象后，WebDAV 看不到这些对象的父目录——根列表里没有该目录，`PROPFIND /<dir>/` 返回 404，但按完整路径访问文件本身正常。

根因有两条：

1. `listAll()` 只 yield `r2_objects.objects`，完全丢弃 `delimitedPrefixes`，列目录这条路从未实现过
2. 集合判定一律依赖 `bucket.head()` + `customMetadata.resourcetype === '<collection />'` 标记对象，直写对象没有这个标记

上游 issue #16/#17 中作者明确拒绝支持直写 R2（"Do not operate R2 directly"），但 PR #27 已放开"往隐式目录写"（`hasCollectionResource` 的前缀兜底），形成"能写进去、看不到、进不去"的不一致状态。RFC 4918 §5.2（"A MUST be a collection that contains a mapping from SEGMENT to B"）与 §9.1（"MUST include a 'response' XML element for each member URL"）要求这种行为必须修正。

**变更（`src/index.ts`，+189 / -35）**

| 位置                                    | 内容                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `listMembers()`（新增，L49/L66）        | 新增 `DavMember` 类型与 `listMembers()` 生成器：带 `include: ['httpMetadata','customMetadata']`，先处理 objects（显式目录标记 / 普通文件）再处理 `delimitedPrefixes`，用 `seen` 集合按 path segment 去重；每页同时收集两者以正确处理 1000 条分页上限。**`listAll()` 保持原样**，避免影响 LOCK / COPY / MOVE 的递归路径 |
| `writeCollectionMarker()`（新增，L248） | 抽出"写集合标记对象"的逻辑（与 MKCOL 相同的表示），供 COPY/MOVE 为隐式集合创建目标标记                                                                                                                                                                                                                                 |
| `generate_propfind_response()`（L1257） | 新增第三个参数 `syntheticCollectionKey`：合成目录无底层 R2 对象，属性沿用 `fromR2Object(null)`（与根集合一致），仅 href 由 key 推导                                                                                                                                                                                    |
| `handle_propfind()`                     | `head()` 为 null 时改为用 `hasCollectionResource()` 判定，成立则按隐式集合处理而非 404；Depth:1 分支改用 `listMembers()`；Depth:infinity **保持不变**（加注释说明理由）                                                                                                                                                |
| `handle_get()` 目录分支                 | 判空逻辑放宽为 `hasCollectionResource()`；HTML 列表改用 `listMembers()`，合成目录渲染成带 `/` 的链接                                                                                                                                                                                                                   |
| `handle_delete()`                       | `head()` 为 null 时用 `hasCollectionResource()` 判定；集合删除后仅在标记对象存在时才 `delete(resource_path)`                                                                                                                                                                                                           |
| `handle_copy()` / `handle_move()`       | 源资源为隐式集合时不再 404；隐式集合无标记对象可复制/移动，改为在目标位置调用 `writeCollectionMarker()` 写入显式标记，保证 COPY/MOVE 保持资源类型（RFC 4918 §15.9）                                                                                                                                                    |

**与方案文档的一处偏差**

方案 §5.3 原计划让合成目录的 `creationdate` / `getlastmodified` 返回 404 propstat。实际实现改为复用 `fromR2Object(null)`，即与**根集合当前的行为完全一致**（`creationdate`/`getlastmodified` 取当前时间，`getcontentlength` 为 0，`displayname` 为 undefined → 404）。理由：避免"根集合"和"隐式集合"这两个同类资源出现两种表现；且 §15.7 的 MUST 只在 GET 返回 `Last-Modified` 头时触发，目录 GET 不返回该头。**耦合约束依旧成立**：将来若给目录 GET 加 `Last-Modified`，必须同时为合成目录实现 `getlastmodified`。

**新增测试 `tests/implicit-collections.sh`（30 条断言）**

litmus 只用 MKCOL 建目录，**覆盖不到隐式目录**，因此新增独立回归脚本。覆盖：根级直写对象、隐式目录在其父目录中出现、`PROPFIND`/`GET` 可进入、多级嵌套隐式目录、同名显式+隐式只报告一次（§5.2 一个 path segment 一个映射）、显式空目录不回归、隐式目录可删除、隐式目录 MOVE/COPY、任意列表无重复 href、普通对象与同名隐式集合冲突时以对象为准。脚本在 DAV_URL 不可达时会自行拉起 `wrangler dev` 并在退出时清理，测试数据写在 `/_regress/` 前缀下并自动清除。
