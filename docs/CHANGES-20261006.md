# 变更记录 2026-10-06

## 2026-10-06 18:15:15 — 支持 R2 隐式目录（implicit collection）

**背景与方案**

完整分析与方案见 `docs/2026-10-06-implicit-collection-plan.md`。问题：直接从 R2 侧（控制台 / S3 API / `wrangler r2 object put`）写入对象后，WebDAV 看不到这些对象的父目录——根列表里没有该目录，`PROPFIND /<dir>/` 返回 404，但按完整路径访问文件本身正常。

根因有两条：

1. `listAll()` 只 yield `r2_objects.objects`，完全丢弃 `delimitedPrefixes`，列目录这条路从未实现过
2. 集合判定一律依赖 `bucket.head()` + `customMetadata.resourcetype === '<collection />'` 标记对象，直写对象没有这个标记

上游 issue #16/#17 中作者明确拒绝支持直写 R2（"Do not operate R2 directly"），但 PR #27 已放开"往隐式目录写"（`hasCollectionResource` 的前缀兜底），形成"能写进去、看不到、进不去"的不一致状态。RFC 4918 §5.2（"A MUST be a collection that contains a mapping from SEGMENT to B"）与 §9.1（"MUST include a 'response' XML element for each member URL"）要求这种行为必须修正。

**与方案文档的一处偏差**

方案 §5.3 原计划让合成目录的 `creationdate` / `getlastmodified` 返回 404 propstat。实际实现改为复用 `fromR2Object(null)`，即与**根集合当前的行为完全一致**（`creationdate`/`getlastmodified` 取当前时间，`getcontentlength` 为 0，`displayname` 为 undefined → 404）。理由：避免"根集合"和"隐式集合"这两个同类资源出现两种表现；且 §15.7 的 MUST 只在 GET 返回 `Last-Modified` 头时触发，目录 GET 不返回该头。**耦合约束依旧成立**：将来若给目录 GET 加 `Last-Modified`，必须同时为合成目录实现 `getlastmodified`。

**新增测试 `tests/implicit-collections.sh`（30 条断言）**

litmus 只用 MKCOL 建目录，**覆盖不到隐式目录**，因此新增独立回归脚本。覆盖：根级直写对象、隐式目录在其父目录中出现、`PROPFIND`/`GET` 可进入、多级嵌套隐式目录、同名显式+隐式只报告一次（§5.2 一个 path segment 一个映射）、显式空目录不回归、隐式目录可删除、隐式目录 MOVE/COPY、任意列表无重复 href、普通对象与同名隐式集合冲突时以对象为准。脚本在 DAV_URL 不可达时会自行拉起 `wrangler dev` 并在退出时清理，测试数据写在 `/_regress/` 前缀下并自动清除。
